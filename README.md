# SDM InfraOps

📋 **About**  
**Skyline.DataMiner.SDM.InfraOps** is the umbrella name for this Standard Data Model (SDM) repository, which provides a strongly‑typed, high‑performance API for managing your infrastructure within the DataMiner ecosystem.  
It is delivered as a set of NuGet packages covering two primary functional domains:

- **Asset Management** — Assets, Ports, Classes, Types, Holders, Locations  
- **Facility Management** — Facility metadata, geospatial attributes, hierarchical facility structures  

---

## 🚀 Key Features

### Strongly‑Typed Infrastructure Modeling
- 🔧 Rich models for Assets, Device Types, Data Ports, Power Ports, Locations, and more  
- 🧩 Clear domain boundaries for Asset & Facility management  
- 🏷️ Reference‑safe relationships between SDM entities   

### Multi‑Context Integration
- 🤖 Automation helpers  
  - engine.GetAssetManagementApiHelper()  
  - engine.GetFacilityManagementApiHelper()
- 🔌 Protocol helpers  
  - protocol.GetAssetManagementApiHelper()  
  - protocol.GetFacilityManagementApiHelper()
- 🧠 GQI helpers  
  - args.DMS.GetAssetManagementApiHelper()  
  - args.DMS.GetFacilityManagementApiHelper()

### Developer Experience
- 🧪 Extensive unit test suite (CRUD, Filters, Paging, Bulk)  
- 🧱 Eight NuGets separating common logic from host‑specific entry points  
- 🔧 Customizable repositories via Extensions and Middleware partial classes

## 🔧 Core Usage

### ▶️ Create
```csharp
var api = engine.GetAssetManagementApiHelper();
var asset = new Asset { AssetName = "Core Switch A1" };
var created = api.Assets.Create(asset);
```

### 🔄 CreateOrUpdate
```csharp
api.Assets.CreateOrUpdate(asset);
api.Assets.CreateOrUpdate(new[] { assetA, assetB });
```

### 📄 ReadPaged
```csharp
var results = api.Assets.ReadPaged(filter, 100);
```

### ❌ Delete
```csharp
api.Assets.Delete(assetToDelete);
```

### 📝 Best Practices
Use bulk operations, typed exposers, paged reads, GUIDs, helper caching, etc.

## 🏗️ Code Generation Strategy

This repository uses a **committed generated output** pattern for its DOM storage layer. Understanding this is important for contributors.

### Generated Files

The following files are **auto-generated** and should not be edited manually:

| File(s) | Generator | How to Regenerate |
|---------|-----------|-------------------|
| `SharedMappers/DomIds.cs` | **Dom Editor** automation script (DataMiner) | Run the *Generate Code* feature in the Dom Editor against the live DataMiner system |
| `SharedMappers/**/Mappers/*.g.cs` | `Skyline.DataMiner.SDM.CodeGenerator` | Re-enable the source generator and rebuild |
| `*/DOM Repositories/**/*.g.cs` | `Skyline.DataMiner.SDM.CodeGenerator` | Re-enable the source generator and rebuild |
| `*/Exposers/*.g.cs` | `Skyline.DataMiner.SDM.CodeGenerator` | Re-enable the source generator and rebuild |

All generated files contain an `<auto-generated>` header block identifying their origin.

### Why Are `[SdmDomStorage]` and `[GenerateExposers]` Commented Out?

The model classes (e.g. `Asset`, `AssetClass`, `Facility`) have the SDM source-generator attributes commented out:

```csharp
// [GenerateExposers]
// [SdmDomStorage("(slc)asset_management")]
public class Asset : SdmObject<Asset>
```

Similarly, the `Skyline.DataMiner.SDM.SourceGenerator` package reference is commented out in both `.csproj` files.

**This is intentional.** The generated output (`*.g.cs` files) has been committed to the repository and is used directly. The source generator is disabled to prevent automatic regeneration during CI builds, which would overwrite the committed files (and could introduce drift if the DOM definitions on the live system differ from what is tracked in source control).

The team is evaluating whether to re-enable the full SDM source-generator workflow in a future iteration. Until that decision is made, **do not uncomment the attributes or the package reference** without team alignment. Any regeneration should be done deliberately and reviewed carefully before committing.

### `DomIds.cs` — Dom Editor Generated Mapping

`SharedMappers/DomIds.cs` is generated by the **Dom Editor → Generate Code** feature in DataMiner, not by the SDM source generator package. It provides type-safe constants for DOM definition IDs, section IDs, and field descriptor IDs. This approach significantly reduces the risk of GUID-related human errors when writing DOM mappers.

To update `DomIds.cs`, run the *Generate Code* action from the Dom Editor automation script against the DataMiner system holding the latest DOM module definitions.
